Approved system design · 2026-08-31

Sub2API
配额中心

为真实 Sub2API Key 增加一个独立、可审计的用户门户：展示用户自己的 5h / 7d 美金额度，并把管理员选定的账号池 5h / 7d 状态安全地公开给全体登录用户。

Go 1.26SQLite / WALVue 3 SPA单二进制交付Sub2API v0.1.183
核心决策架构身份与绑定同步接口界面安全交付
01 · Decisions

先锁定执行边界，再谈展示

唯一的配额执行者是 Sub2API。 门户不代理模型请求、不保存分发 Key 原文、不建立第二套计费账本。上游必须处于非 simple 模式，并在真实 Key 上同时配置正数 rate_limit_5h 与 rate_limit_7d。

兼容基线

官方 Sub2API v0.1.183。只调用五类既定 Admin API，不依赖上游内部数据库。

状态而非账本

SQLite 保存用户、会话、绑定、公开选择和最后快照；不保存历史计费流水。

明确接受

沿用上游原生滚动窗口语义，也接受高并发临界点可能出现的少量超额。

02 · Architecture

回环监听的 sidecar，浏览器与模型流量完全分离

浏览器登录、我的 Key、公开账号池、管理员后台
→
Nginx → PortalHTTPS 终止；Go 标准库 HTTP；Vue 通过 go:embed 内嵌
↔
SQLite + Sub2API本地身份/快照；Admin API 只读同步

模型请求路径

模型客户端携带真实 Key 直接访问 Sub2API。门户不在数据面，因此自身故障不会改变已有 Key 的调用路径。

控制与展示路径

管理员通过门户绑定已有 Key、发布账号；同步器取得状态并写入最后快照，用户页面只读该快照。

03 · Identity

单管理员、单 Key 绑定、可撤销会话

首次初始化

  • 启动生成 30 分钟 Setup Token
  • 创建唯一管理员
  • 校验 Base URL、Admin API Key、固定 Key 所有者
  • 明确确认非 simple 模式

普通用户

  • 一个当前 Key，数据库唯一约束
  • 只看自己的额度与全局公开账号
  • 可以自行修改密码
  • 不能读取完整 Key

管理员

  • 创建用户时原子绑定 Key
  • 停用、软删除、重置密码、换绑/解绑
  • 选择公开账号池
  • 维护上游连接设置

停用、重置密码或软删除会撤销目标用户的全部会话；软删除不会修改或删除上游 Key。上游 Key 消失时绑定进入“需要换绑”，限额不合规时进入“配置异常”，系统不按名称自动猜测替代 Key。

04 · Synchronization

三个独立节奏，一套清晰的新鲜度语义

15s

固定所有者 Key

45 秒没有成功结果即陈旧；完整 Key 和最后使用 IP 解析后立即丢弃。

5min

账号目录

更新管理员可发布清单；邮箱在普通用户视图中脱敏，无邮箱使用持久化随机别名。

60s

已公开账号用量

调用批量接口且 force:false；保留官方 updated_at，不承诺数据本身每分钟变化。

可靠性

最多 4 个并发任务；同类触发 singleflight 合并；带抖动重试并指数退避，最高 5 分钟。

失败呈现

上游 401、429、5xx、超时或 schema 错误都保留最后成功快照，并返回 as_of / last_success_at / stale。

05 · Interfaces

统一 envelope，角色边界落在服务端

接口组用途访问策略
/healthz · /readyz进程存活；初始化、数据库与主密钥就绪无需会话；ready 不依赖上游在线
/api/setup/*初始化状态与一次性完成向导仅未初始化时可变更，要求有效 Setup Token
/api/auth/*会话、登录、注销、改密Cookie 会话；变更需要 CSRF
/api/me/dashboard我的 Key 额度及公开账号池任何已启用登录用户
/api/admin/users用户、密码重置、Key 绑定仅管理员
/api/admin/upstream-keys掩码 Key、限额合规与占用状态仅管理员
/api/admin/pool账号清单和公开选择仅管理员
/api/admin/settings · sync连接设置和手动同步仅管理员，审计变更

成功响应：{"data": ...}；错误响应：{"error":{"code":"...","message":"..."}}。公开窗口类型固定为 KeyWindowView、PoolWindowView 与 SnapshotMeta；空 reset_at 表示“尚未启动”，Provider 缺失窗口必须显示“未提供”。

06 · Experience

浅色、克制而有生命力的状态界面

信息结构

登录、初始化、普通用户工作台、用户管理、账号池、连接设置。工作台以“我的 Key”状态带开场，随后是全平台公开账号表；管理编辑统一使用右侧抽屉。

动态反馈

数字补间、额度环、进度条、列表交错、筛选重排、抽屉、骨架屏和 Toast。键盘焦点完整可见，并尊重 prefers-reduced-motion。

暖白底，圆角 6–8px；内嵌 Noto Sans SC、Sora、JetBrains Mono，避免生产环境依赖外部字体 CDN。

07 · Security

秘密最小化，但不掩盖全权限凭据风险

凭据

密码 Argon2id；Admin API Key AES-256-GCM；主密钥只在环境；会话只存 Token 摘要；分发 Key 仅存掩码。

网络

默认监听 127.0.0.1:2560；生产 HTTPS；禁止上游重定向、限制响应大小与超时；私网 HTTP 必须明确确认。

不可回避的风险

Admin API Key 拥有上游全权限。数据库与主密钥同时泄露即可解密；root、管理员会话和恶意上游均不在防护范围内。

08 · Delivery

单实例、单二进制、可回退升级

运行形态

  • Linux amd64 / arm64
  • 加固 systemd unit
  • Nginx HTTPS 示例
  • 环境文件权限 0640
  • 状态目录权限 0750

验证门槛

  • Go 单测、race、vet
  • 假 Sub2API HTTP 集成测试
  • 哨兵秘密泄露扫描
  • Vitest 与 TypeScript
  • Playwright 桌面/移动流程
升级与备份决策

安装器在停服后复制同一时刻的 app.db、app.db-wal、app.db-shm 与旧二进制；新服务不能稳定运行则恢复旧程序和升级前数据库快照。默认卸载保留配置和数据，永久清除要求固定路径校验与完整确认词。

09 · Exclusions

首版明确不做

不代理模型请求；不创建、删除或展示完整上游 Key；不做多管理员、多 Key、邮件找回、MFA、趋势历史、Docker、多实例、独立计费核验或 Provider 缺失窗口推算。更换 Base URL 或固定所有者之前必须先解绑用户、取消账号发布，再轮换连接标识并清空旧快照。
