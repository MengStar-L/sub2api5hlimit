1. 已确认决策

应用默认监听 0.0.0.0:2556，允许浏览器直接使用 http://服务器IP:2556；SUB2API_LIMIT_COOKIE_SECURE=false，Nginx HTTPS 作为可选配置。
  • 目标仓库：https://github.com/MengStar-L/sub2api5hlimit，当前为空。
  • 首个版本：v0.1.0，推送 Tag 后触发自动构建和 GitHub Release。
  • 产品名与二进制/服务名继续使用 sub2api-limit-portal，避免不必要的运行兼容性变化。
  • Go module 更新为 github.com/MengStar-L/sub2api5hlimit，文档链接同步指向新仓库。

2. 网络与安全边界

浏览器 → HTTP :2556 → Go 服务；可选：浏览器 → HTTPS :443 → Nginx → HTTP :2556

  • Go 服务绑定所有 IPv4 接口，满足 0.0.0.0:2556 的部署要求。
  • 默认允许公网直接访问 TCP 2556，不由安装器管理防火墙或安全组。
  • Nginx 示例保留，供管理员自行选择 HTTPS、域名和证书配置。
  • README 说明明文 HTTP 没有传输加密，但不把 HTTPS 设为安装前置条件。
责任边界：安装器只负责服务正常监听公网端口；TLS、防火墙和访问控制由部署管理员自行配置。

4. 自动发布

新增 .github/workflows/release.yml，仅在匹配 v* 的 Tag 推送时运行：

  1. 检出源码，安装 Go 1.26 与 Node.js 22。
  2. 执行 Vue typecheck、Vitest、生产构建，以及 go test ./...、go vet ./...。
  3. 从 Tag 注入程序版本，以 CGO_ENABLED=0 构建 Linux amd64 与 arm64。
  4. 每个架构生成独立 tar.gz，内含既定的 dist/、packaging/、scripts/ 和 README 布局。
  5. 生成 SHA-256 清单，使用仓库自带的 GITHUB_TOKEN 创建 GitHub Release 并上传产物。
git push origin main
git tag -a v0.1.0 -m "Release v0.1.0"
git push origin v0.1.0

5. 安装与升级体验

  • Linux 用户从 Release 下载与 CPU 架构对应的压缩包和 SHA256SUMS。
  • 校验、解压后运行 sudo bash scripts/install.sh；安装器创建服务账号、主密钥、目录和 unit。
  • 若仅检测到旧版 /usr/local、/etc/sub2api-limit-portal 或 /var/lib/sub2api-limit-portal 布局，安装器立即中止并指向 README 的人工迁移步骤，不生成新主密钥或空数据库。
  • 首次安装自动启用并启动服务，管理员通过 journalctl 获取 30 分钟 Setup Token。
  • 再次运行同版本或新版本安装器视为升级：停止服务，一致备份 SQLite/WAL/SHM，替换二进制，失败则回滚。
  • README 提供公网 HTTP 访问地址、可选 Nginx 配置，以及 start、stop、restart、status、enable、journalctl、备份和卸载命令。
